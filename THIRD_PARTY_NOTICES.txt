WebViewUpgrade
--------------
Author:    JonaNorman
Source:    https://github.com/JonaNorman/WebViewUpgrade
License:   Apache License, Version 2.0 (full text below)
Included:  the library's `core` module (91 class files), as
           com.norman.webviewup.lib.** (package name unchanged)

Spotify Web's experimental custom WebView engine (introduced in version 1.50)
is built on top of this library. It lets the app load a newer Android System
WebView from a file inside its own storage instead of the phone's WebView.
Only Spotify Web is affected; other apps keep the system WebView. The library
does this by making the Android WebView machinery resolve its provider to a
package the app supplies.

What Spotify Web uses from the library
  - WebViewUpgrade.upgrade(source): called at application start, before any
    WebView exists, to switch the app's WebView to the imported package.
  - WebViewUpgrade.isCompleted(): tells the app whether the custom engine is
    actually active (shown as "(custom)" and in the engine status dialog).
  - UpgradeFileSource and UpgradeSource.prepare(OnPrepareCallback): the
    imported WebView APK is wrapped in a file source and prepared once at
    import time (copy and native-library extraction), so later launches swap
    the engine inline. The app implements UpgradeSource$OnPrepareCallback
    (restart on success, message on error) and manages the library's prepared
    copy (the package_webview/<md5> folder) when pruning and removing it.
  - util.RestartUtil.restart(): relaunches the app after import, replace,
    remove and re-apply.
  - util.ProcessUtils.isMainProcess(): limits the swap to the main process.
  - util.FileUtils.md5(): used to find the folder the library created for the
    current file.
  - Used unmodified and not called directly by the app: the provider
    replacement hooks (WebViewReplace, hook.*, service.*, reflect.*) and the
    sandbox support (sandbox.*, plus the five StubSandboxedProcessService0-4
    services declared in the app manifest, one per sandboxed process), which
    let WebView's multi-process mode load the custom engine too.
  - Included but not used by the app: UpgradeAssetSource,
    UpgradeDownloadSource, UpgradePackageSource.

Modifications (Apache License 2.0, section 4(b))
  - com/norman/webviewup/lib/util/RestartUtil: in
    restart(Application, Runnable) the killBackgroundProcesses call is wrapped
    in try/catch (Throwable) so a refused kill no longer stops the relaunch.
    The change is marked in the file with the comment
    "# v1.50: a refused/failed kill must not stop the restart".
  No other file of the library was modified.

Spotilol
--------
Author:    lyssadev
Source:    https://github.com/lyssadev/Spotilol (the repository is currently
           unavailable)
License:   not verified. The repository is down, so its license could not be
           checked. Adapted from the v1.2.4 build.
Included:  no files or library; the parts below were re-implemented in this
           app's own classes.

Spotify Web's Debug Logging and Logger (introduced in version 1.52) are adapted
from the debug logger of Spotilol:
  - the in-memory log store (entry, level and store classes, merged into one
    class here)
  - the dbg / clearDebugLog bridge between the web page and the app
  - the page-side dbg helpers
  - capturing the WebView's console messages into the log
  - the search filter (same grammar, without the pkg: and mine keys)
  - the Logger dialog (rebuilt with plain Android views)
Changes for Spotify Web include a per-source buffer split, the Source and Level
buttons, pause behavior, and logging only while Debug Logging is switched on.

The Spotifuck Mobile userscript (loaded by the app from GitHub, not part of the
APK) adapts Spotilol's ToastFix, which restyles the web player's pop-up
messages: the rounded pill shape, the title and button styling, the "Dark"
colours, the entrance animation, swipe-to-dismiss, the exit animation and the
stack spacing. The script re-implements the logic in its own code and credits
ToastFix in its header. Its AMOLED and Normal looks, the toast positioning above
the app's player and nav bars, and the round-icon fix are its own.

Only these parts are based on Spotilol; the rest of Spotify Web is not.


Eruda
-----
Author:    liriliri
Source:    https://github.com/liriliri/eruda (https://eruda.liriliri.io/)
License:   MIT License (full text below)
Included:  eruda.js, version 3.4.3, from the npm package, as assets/eruda.js.
           Only change: the trailing "//# sourceMappingURL" comment line
           (it pointed to a source map that is not shipped) was removed.

Spotify Web's Eruda Console (introduced in version 1.61) is the Eruda library,
bundled in the app. It is a developer console (Console, Elements, Network,
Resources, Sources, Info, Snippets and Settings tabs) that can be shown on the
web player page. It is off by default and only runs while Settings > Eruda
Console is switched on; nothing is loaded from the network.

What Spotify Web does with the library
  - ErudaConsole (new): reads assets/eruda.js, runs it in the page and calls
    eruda.init() with the "Dark" theme, eruda.show() when the switch is turned
    on, and eruda.destroy() when it is turned off.
  - The library file is not modified. The app wraps it in a small function when
    it runs it; the file itself is shipped as is.
